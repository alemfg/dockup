ARBX v7.1 — 4 Bug Fixes from Live Log Analysis

BUG FIXES
────────────────────────────────────────────────────────────────────────

[CRITICAL] api/routes/market.py — NameError: 'pairs' not defined
  The `get_spreads()` endpoint iterated `for pair in sorted(pairs)` but
  `pairs` was never assigned in that function. `all_prices` was built
  above, but the derivation step was missing. This caused a 500 on every
  GET /api/market/spreads call, meaning the entire Spatial Arb panel
  was broken at runtime — the UI showed empty/error state on every load.
  Fix: added `pairs = list({p["pair"] for p in all_prices})` before the
  loop.

[HIGH] worker/worker.py — 'str' object has no attribute 'keys' (binance)
  `_fetch_and_publish_balances()` called `fetch_tickers()` with no args,
  then iterated the result as `{sym: t["last"] for sym, t in tickers.items()
  if t.get("last")}`. Binance's CCXT response includes non-dict entries
  (e.g. an "info" key whose value is a JSON string). Calling `.get("last")`
  on a string throws AttributeError. The outer error handler caught it and
  logged `Worker error: 'str' object has no attribute 'keys'` — once every
  2 seconds continuously, burying all other log output.
  A secondary issue: `raw.get("total", {}).items()` can include non-numeric
  asset entries (e.g. "info") which also fail on the `not total` check.
  Fix: added `isinstance(t, dict)` guard in the ticker comprehension;
  added `isinstance(total_dict, dict)` guard on the raw balance dict;
  added `isinstance(total, (int, float))` guard before processing each
  asset entry.

[MEDIUM] brain/fleet/monitor.py — false mass respawn at startup (~11min)
  All workers simultaneously showed "Heartbeat lost — worker presumed dead"
  at 23:18, approximately 11 minutes after startup. Workers were healthy —
  prices were still publishing — but the fleet monitor's consumer group had
  fallen behind during the startup burst (1000+ heartbeats in seconds with
  batch read of only 50 at a time). The unconsumed backlog caused the
  monitor's xreadgroup to block waiting for new messages while the unread
  old ones were not counting as "recent", so is_dead() fired for all workers
  simultaneously.
  Fix 1: increased xreadgroup count from 50 → 200 to drain bursts faster.
  Fix 2: added `r.xtrim(STREAM_HEARTBEATS, maxlen=5000, approximate=True)`
  after each batch to cap stream length and prevent unbounded lag buildup.

[LOW] brain/listing_monitor.py — CoinGecko 401 every 5 minutes
  The /coins/list/new endpoint now requires authentication. The monitor was
  calling it without any headers, always getting 401, and spamming the log
  every poll cycle.
  Fix: reads COINGECKO_API_KEY from env; if set, sends it as
  `x-cg-demo-api-key` header (CoinGecko demo/free tier format). If still
  401 (no key configured), log message now includes the actionable URL
  instead of just the status code.
