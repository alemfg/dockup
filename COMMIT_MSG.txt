ARBX v4.4.0 — .env.local Pattern · Version Strings Unified

── .env Split — Never Lose Your Config on Upgrade ──────────────────────────────

The old single .env file created a painful upgrade situation: the new release
ships .env.example with new variables, but your .env has your API keys.
Merging them manually every time was error-prone and annoying.

v4.4 adopts the .env.local pattern used by Next.js, Laravel, and Vite:

  config/.env          ← SHIPPED WITH EVERY RELEASE
                         Safe defaults, no secrets. Safe to overwrite.
                         Committed to git. Contains every tunable with
                         its recommended default value.

  config/.env.local    ← YOUR PERSONAL FILE. Never touched by upgrades.
                         API keys, passwords, and your personal overrides.
                         In .gitignore. Created once from .env.local.example.

  config/.env.example      ← Full reference doc. Every variable explained.
  config/.env.local.example ← Minimal template for .env.local (NEW)

Load order: .env first, then .env.local with override=True. Your values always
win. After adding a new key to .env.local, press "Reload Brain Config" or
"Reload Workers Config" in the dashboard — no restart needed.

── Upgrade workflow from v4.3 ───────────────────────────────────────────────────

1. Create config/.env.local from the example:
     cp config/.env.local.example config/.env.local

2. Move your secrets from your old .env into .env.local:
     POSTGRES_PASSWORD=your_real_password
     BINANCE_API_KEY=your_key
     BINANCE_API_SECRET=your_secret
     (plus any personal overrides)

3. From now on, never edit config/.env again. Only edit .env.local.

4. On every future upgrade: extract the new ZIP, your .env.local is untouched.

── config/loader.py changes ─────────────────────────────────────────────────────

Module-level load order:
  load_dotenv(".env")                  # shipped defaults
  load_dotenv(".env.local", override=True)  # personal overrides win

reload_config() mirrors the same two-file reload with override=True so that
"Reload Brain Config" picks up changes from both files.

Module-level path constants _ENV_PATH and _ENV_LOCAL_PATH replace the inline
Path() call. Used in both the startup load and reload_config().
